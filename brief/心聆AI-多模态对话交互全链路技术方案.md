# 心聆AI — 多模态对话交互全链路技术方案

## 1. 方案概述

### 1.1 方案定位

本方案为智能对话系统构建完整的可扩展多模态交互全链路能力。在既有文本对话基座之上，于**输入侧**扩展语音流式识别与端侧面部情绪感知双通道，形成文本、语音、视频表情三维度联合感知；于**输出侧**扩展语音流式合成、二维虚拟形象（Live2D）、三维虚拟形象（VRM）与写实数字人（WebRTC）四通道，形成文本、语音、2D形象、3D形象、数字人形象五维度协同表达。全链路形成「多模态感知输入 → 语义联合推理 → 多模态表达输出」的端到端交互闭环，显著增强心理陪伴对话的沉浸感、共情精准度与情感传达力。

架构采用**输入模态注册表 + 输出模态注册表**的双注册表驱动模式，输入侧与输出侧的模态通道均以插件化方式注册与编排，后续可根据不同需求场景灵活扩展输入模态（如生理信号、环境感知等）与输出模态（如AR/VR沉浸式表达、全息投影等），从根本上保障项目的模态扩展性与场景适配能力。

### 1.2 核心设计原则

| 原则 | 描述 |
|------|------|
| 输入侧多源联合感知 | 文本语义、语音语调情绪、面部微表情三维度联合输入，构建用户真实情绪状态的完整感知信号空间 |
| 输出侧多通道协同表达 | 流式文本、语音音频、二维虚拟形象、三维虚拟形象、写实数字人形象五通道协同输出，按场景需求灵活组合，实现应答的情感丰满度与拟人化 |
| 模态插件化可扩展 | 输入侧与输出侧模态通道均以插件化方式注册至模态注册表，新增模态只需实现标准接口并注册，无需修改核心调度逻辑，具备开放-封闭特性 |
| 端云分层解耦 | 感知算力下沉端侧（面部推理、虚拟人渲染），语义决策汇聚云端（LLM推理、情绪分析），职责严格隔离 |
| 同源一体化推理 | 单模型单次推理联合生成对话正文、情绪标签与动作指令，从源头消除多模型并行推理的语义失步风险 |
| 流式交互零阻塞 | 全链路流式管道架构，指令前置下发、正文持续推送、音频边合成边播放，消除任意环节的阻塞等待 |
| 隐私合规架构级保障 | 原始生物特征数据零出域传输，仅上行结构化数值特征，满足心理咨询场景个人信息保护合规要求 |

## 2. 输入侧：多模态联合感知

### 2.1 文本输入通道

用户直接输入文本内容，经语义编码后注入LLM上下文窗口，作为对话交互的基础输入模态。该通道为系统默认常驻通道，无需额外启停控制。

### 2.2 语音输入通道 — ASR流式识别长连接管理

#### 2.2.1 架构设计

系统基于云端智能语音服务实现自动语音识别（ASR）长连接管理，采用WebSocket全双工长连接复用策略，按用户维度维护独立的识别实例，支持多轮连续语音识别而无需反复建立连接。

#### 2.2.2 核心机制

| 机制 | 实现策略 | 目标 |
|------|---------|------|
| 并发连接容量管控 | 以用户标识为键、识别会话上下文为值构建并发安全会话注册表，容量阈值原子检查 | 防止系统资源耗尽 |
| 用户级连接隔离 | 每用户独立识别实例与回调通道 | 消除会话串扰风险 |
| 自动重连与令牌刷新 | 定时任务调度器周期性刷新访问令牌，令牌更新后标记活跃会话待重建 | 保障网络波动与服务端令牌过期场景下的持续可用性 |
| 空闲会话超时淘汰 | 定时扫描会话注册表，超空闲阈值会话自动执行资源释放与连接关闭 | 回收闲置资源 |
| 优雅关闭保护 | 原子关闭标记确保回调丢弃保护 | 防止服务端延迟回调污染已释放会话状态 |

该设计将语音识别从传统「单次请求-响应」模式升级为「长连接复用 + 流式识别」模式，显著降低建连开销与首字识别延迟，同时通过原子生命周期管理消除并发竞态条件。

### 2.3 面部情绪感知通道 — MediaPipe端侧推理

#### 2.3.1 架构定位

端侧本地化推理感知模块，作为大语言模型对话系统的**多模态辅助输入通道**。摄像头原始视频帧数据全程驻留于客户端浏览器内存空间，推理输出经标准化映射后的面部BlendShape运动参数与自然语言情绪状态描述，以结构化提示词形式注入LLM上下文窗口，构建「文本语义 + 面部情绪」双维度联合感知的对话增强机制。

#### 2.3.2 推理输出能力

Face Landmarker模型端侧推理后输出两类核心特征数据：

- **468点3D面部关键点坐标**：精确表征眉弓、眼裂、鼻唇沟、口裂、下颌等面部解剖标志点的三维空间位置与姿态；
- **52维BlendShape面部肌肉运动系数**：连续量化皱眉肌收缩、额肌上提、颧大肌牵拉、降口角肌激活、眼轮匝肌紧缩、咬肌紧张等微表情运动参数。该连续参数空间可精细辨识「言语表达与面部真实情绪失步」的矛盾状态，为核心心理陪伴场景提供不可替代的感知维度。

#### 2.3.3 时域降噪与防抖策略

| 策略 | 配置 | 目标 |
|------|------|------|
| 滑动窗口均值滤波 | 缓存连续5帧BlendShape参数向量，逐维度求均值 | 抑制瞬目反射、头部微动、光照突变等瞬态噪声 |
| 极值剔除 | 窗口内各维度离群值检测与剔除 | 消除特征跳变 |
| 帧间节流 | 300ms推理间隔 | 平衡实时性与设备功耗 |
| 置信度门控 | 人脸检测置信度 < 0.6 判定为无效采样 | 规避低质量输入误判 |

#### 2.3.4 面部特征-情绪语义映射

将52维连续数值参数空间映射为大语言模型可理解的自然语言情绪状态描述：

| 语义维度 | 映射逻辑 | 输出示例 |
|---------|---------|---------|
| 主情绪标签 | 核心肌肉参数组合阈值判定 | 愉悦、焦虑、低落、平静、烦躁 |
| 面部状态详述 | 多参数联合分析连续状态自然语言描述 | "皱眉肌收缩、眼睑张力偏高，面部呈现隐性紧张状态" |
| 情绪一致性判定 | 文本语义极性与面部情绪极性对比 | 一致 / 矛盾（需重点关注隐性情绪） |

**核心映射规则**：

- **积极情绪态**：颧大肌激活 + 额肌舒展 + 面部整体肌张力低 → 愉悦、放松、平静
- **消极情绪态**：皱眉肌收缩 + 眼轮匝肌紧缩 + 降口角肌激活 + 咬肌紧张 → 焦虑、低落、压抑、烦躁
- **中性情绪态**：各维度参数处于基线附近，无显著极性偏移 → 情绪平稳
- **伪装情绪态**：面部肌肉运动模式呈非自发性特征（如刻意微笑缺乏眼轮匝肌协同收缩）→ 可辨识情绪伪装

#### 2.3.5 隐私保护机制

- **原始生物特征数据零出域**：摄像头视频流与人脸像素数据全程驻留浏览器内存沙箱，不执行网络传输、服务端缓存或持久化存储
- **最小化数据上行**：仅传输结构化情绪描述文本与数值特征向量（数十字节），无生物图像信息泄露向量
- **用户自主管控**：面部感知功能显式启停控件，终止后立即停止端侧推理与数据采集流水线
- **无持久化留存**：端侧缓存为易失性内存数据，页面生命周期结束时自动销毁

## 3. 云端决策层：同源一体化推理与流式调度

### 3.1 大模型同源一体化输出机制

对话正文、情绪标签与动作指令均由同一大模型基于同一上下文窗口联合生成，从推理源头保证文本语义、情绪状态与动作语义的严格一致性。

采用 **头部标记指令 + 尾部流式正文** 的混合输出格式，兼顾结构化指令的精准解析与文本流式输出的实时体验：

```text
[AVATAR]{"emotion":"xxx","motion":"xxx","outputMode":"xxx"}
对话正文内容（纯自然语言，逐Token流式输出）
```

#### 3.1.1 字段枚举约束

| 字段 | 语义 | 枚举值 |
|------|------|--------|
| emotion | 情绪表情 | `neutral`（平静）、`thinking`（思考）、`sympathetic`（共情）、`serious`（严肃） |
| motion | 肢体动作 | `null`（无动作）、`nod`（点头）、`leanForward`（前倾倾听） |
| outputMode | 输出模态组合 | `text`（纯文本）、`text_voice`（文本+语音）、`text_voice_2d`（文本+语音+2D形象）、`text_voice_3d`（文本+语音+3D形象）、`text_voice_digital`（文本+语音+数字人） |

### 3.2 流式解析与时序调度

云端对大模型流式Token序列执行增量解析，实现 **指令前置下发、正文持续流式推送** 的核心时序效果：

1. 云端维护临时字符缓冲区，持续接收大模型流式Token并追加
2. 监测缓冲区换行符，识别首行换行后立即分割头部指令行与正文起始
3. 对首行执行正则匹配提取结构化指令，完成JSON解析与字段合法性校验
4. 解析成功后根据`outputMode`字段路由至输出模态注册表，激活对应输出通道
5. 立即通过WebSocket下行虚拟人控制指令，提前触发表情动作切换
6. 首行解析完成后，后续Token全部作为对话正文实时流式推送至端侧

### 3.3 多模态Prompt联合组装规范

面部情绪感知数据与语音语调情绪特征作为辅助输入模态，通过结构化注入系统提示词模板，实现文本语义、语音情绪与面部情绪的三维度联合上下文构建：

```text
【系统角色定义】
你是一款专业心理陪伴对话助手，具备多模态情绪感知与共情应答能力。仅提供情绪疏导与心理陪伴服务，不执行临床诊断，不替代专业心理咨询师执业。

【用户实时多模态感知数据】
- 面部主情绪状态：{{primaryEmotion}}
- 面部微表情详述：{{facialStateDetail}}
- 情绪一致性判定：{{isEmotionContradictory ? "言语表达与面部情绪存在失步，优先关注面部隐性真实情绪" : "言语与面部情绪一致"}}
- 语音语调情绪特征：{{voiceEmotionFeature}}

【用户输入文本】
{{userInputText}}

【应答策略约束】
1. 融合文本语义、语音语调情绪与面部微表情感知数据进行联合推理，优先捕捉隐性、压抑、伪装等非显性情绪信号；
2. 应答语气保持温和共情、简洁舒缓，避免说教式表达与专业术语堆砌；
3. 当感知到持续性负面情绪状态时，给予正向情绪疏导，必要时引导用户寻求专业心理援助；
4. 应答内容须严格锚定用户真实情绪状态与文本语义，禁止脱离感知数据生成无关内容。
```

### 3.4 消息处理流程编排

系统采用策略模式实现消息处理器的灵活路由与动态分发。通过依赖注入容器自动收集所有消息处理器实现并注册至输出模态注册表，根据`outputMode`标识与场景需求动态路由至对应处理器组合。

| 处理器类型 | 核心职责 |
|-----------|---------|
| 文本处理器 | WebSocket流式推送大模型文本内容，同步完成消息持久化与缓存更新 |
| 语音处理器 | 叠加TTS流式合成，将大模型输出语义片段实时送入合成器，WebSocket推送文本流与音频流 |
| 二维形象处理器 | 叠加Live2D指令下发，驱动二维虚拟形象表情动作与口型同步 |
| 三维形象处理器 | 叠加VRM参数下发，驱动三维虚拟形象表情动作与口型同步 |
| 数字人处理器 | 叠加WebRTC视频流推流，驱动写实数字人面部口型与微表情帧级同步 |

语音处理器内置中断标志检测机制，流式推送过程中实时检查缓存中断标识，检测到用户中断操作则立即停止推送并执行资源清理，保障中断语义即时生效。该架构实现消息处理逻辑与通信协议的完全解耦，**新增输出模态只需实现对应处理器接口并注册至输出模态注册表**，无需修改核心调度逻辑，具备开放-封闭特性与模态扩展能力。

### 3.5 输出模态场景适配策略

不同交互场景按用户偏好与终端能力自动选择最优输出模态组合：

| 场景类型 | 推荐输出模态组合 | 适配逻辑 |
|---------|----------------|---------|
| 日常陪伴轻交互 | 文本 + 语音 + 2D形象 | 低算力需求，治愈系风格，适配移动端 |
| 沉浸式长期陪伴 | 文本 + 语音 + 3D形象 | 三维空间交互，支持多视角，适配PC端 |
| 正式心理咨询 | 文本 + 语音 + 数字人 | 真人代入感强，适配高信任需求场景 |
| 纯文本模式 | 文本 | 终端无音频能力或用户偏好静默交互 |
| 低配终端降级 | 文本 + 语音 | 端侧无渲染能力时自动降级 |

### 3.6 容错与防抖机制

| 机制类型 | 触发条件 | 降级策略 |
|---------|---------|---------|
| 指令格式容错 | 模型输出格式异常或指令解析失败 | 自动降级为`neutral`平静表情、无动作 |
| 动作指令防抖 | 短时间内重复下发相同动作指令 | 3秒动作冷却窗口，窗口内重复指令自动拦截 |
| 动作互斥管控 | 同一时段存在多个核心动作指令 | 仅执行最新指令，禁止多动作叠加冲突 |
| 面部感知降级 | 摄像头不可用、权限拒绝、光照不足 | Prompt情绪字段填充「无面部情绪感知数据」，退化为纯文本+语音模式 |
| TTS异常熔断 | TTS服务异常或合成超时 | 自动降级为纯文本推送，保障服务可用性 |
| 形象渲染降级 | 端侧GPU/WebGPU不可用或渲染异常 | 自动降级为低一级模态组合（3D→2D→纯语音→纯文本） |
| 数字人推流降级 | WebRTC连接失败或云端GPU资源不足 | 自动降级为3D/2D形象模式，保障交互连续性 |

## 4. 输出侧：多模态协同表达

### 4.1 文本输出通道

流式文本逐Token推送至端侧，端侧执行打字机效果渲染，同步完成消息持久化与缓存更新。该通道为系统默认常驻输出通道，所有输出模态组合均包含文本输出。

### 4.2 语音输出通道 — TTS流式合成管道

#### 4.2.1 架构设计

系统实现文本转语音（TTS）流式合成管理模块，基于云端智能语音服务流式合成协议，按用户维度维护会话上下文（音频输出缓冲流、合成结果回调与合成状态标识）。

#### 4.2.2 核心机制

| 机制 | 实现策略 | 目标 |
|------|---------|------|
| 三级流水线管道 | 大模型流式输出 → 语义片段实时送入TTS合成器 → 音频流WebSocket推送 | 「边生成边合成边推送」，端到端语音响应延迟压缩至首包音频到达时间 |
| 合成状态机 | 原子忙闲标志 + 合成标识精确控制启动/进行/完成 | 同一用户同一时刻仅允许一路TTS合成，CAS自旋保证互斥 |
| 合成标识递增 | 用户主动中断时递增合成标识 | 服务端延迟回调因标识校验失败自动失效，防止过期回调污染全局状态 |
| 异常熔断 | TTS服务异常或合成超时 | 自动降级为纯文本推送，保障服务可用性与体验连续性 |
| 保活心跳 | 文本分片发送间隔超阈值时自动发送保活探测 | 防止连接因空闲超时被服务端断开 |

### 4.3 二维虚拟形象表达通道 — Live2D可视化输出

#### 4.3.1 架构定位

Live2D二维虚拟形象可视化输出通道，作为大语言模型应答的**二维多模态表达层**，将纯文本应答升维为「流式文本 + 情绪表情 + 拟人动作 + 实时口型同步」的联合输出范式。适用于治愈系轻交互、青少年心理疏导等偏好二维风格的场景。

#### 4.3.2 渲染基座

端侧基于Web端Live2D Cubism SDK加载标准moc3格式虚拟人模型，实现Canvas透明渲染与视口自适应布局。纯浏览器端完成可视化呈现，无需本地客户端或推流工具，支持多用户独立渲染实例与独立交互上下文。

#### 4.3.3 三类动画分层管控

| 动画层级 | 驱动源 | 行为描述 | 生命周期 |
|---------|-------|---------|---------|
| 常驻待机动画 | 端侧自治 | 呼吸起伏、瞬目反射、躯体微晃 | 页面加载后持续循环，无交互时保持自然态 |
| 事件触发动画 | 云端指令驱动 | 点头、前倾倾听等预制Motion动画 | 接收指令后单次播放，完毕自动回归待机 |
| 实时口型动画 | 音频振幅自主驱动 | 基于TTS音频实时振幅动态计算嘴部开合参数 | 音频播放期间持续驱动，结束自动归零 |

#### 4.3.4 指令映射机制

端侧维护本地静态映射表，云端仅下行语义化指令标识而不传递具体模型参数，实现端云参数解耦：

- **表情语义映射**：云端`emotion`字段 → 端侧匹配模型五官参数组（眉弓、眼裂、口裂状态参数集）
- **动作语义映射**：云端`motion`字段 → 端侧匹配对应预制Motion3动画资源并触发播放

#### 4.3.5 音画同步驱动

口型同步由端侧自主实现，不依赖云端逐帧控制。通过Web Audio API实时采集TTS音频播放振幅，经平滑阻尼算法计算后，动态修改Live2D模型嘴部开合参数，实现低延迟、高自然度的口型联动。音频播放结束后口型参数自动归零，全程贴合人声节奏。

### 4.4 三维虚拟形象表达通道 — VRM可视化输出

#### 4.4.1 架构定位

VRM三维虚拟形象可视化输出通道，作为大语言模型应答的**三维多模态表达层**，将纯文本应答升维为「流式语音 + 三维表情动作 + 实时口型同步」的联合输出范式。适用于沉浸式长期陪伴、多视角交互等偏好三维风格的场景。

#### 4.4.2 渲染基座

端侧基于Three.js + VRM SDK加载标准VRM格式三维数字人模型，实现WebGPU加速渲染、Canvas透明叠加与视口自适应布局。纯浏览器端完成三维可视化呈现，支持360°拖拽旋转与多视角查看，支持多用户独立渲染实例。

#### 4.4.3 核心渲染能力

| 能力域 | 实现描述 |
|-------|---------|
| 模型加载与初始化 | 加载轻量化治愈系三维模型，初始化标准人形骨骼、表情通道（BlendShape）、物理弹簧效果 |
| 表情参数实时驱动 | 接收云端0~1浮点参数，精准控制标准化表情通道：口裂开合、瞬目、柔和微笑、低落、眉弓情绪 |
| 头部微动作模拟 | 内置随机微小头部偏移与轻柔瞬目动画，避免静态僵硬，模拟真人倾听自然态 |
| 音频帧同步渲染 | 音频播放时间轴与表情参数时间戳精准对齐，杜绝音画错位 |
| 参数插值平滑 | 表情参数帧间插值平滑处理，避免突变卡顿与闪烁 |

#### 4.4.4 音画同步驱动

口型同步由端侧自主实现，通过Web Audio API实时采集TTS音频播放振幅，经平滑阻尼算法计算后，动态修改VRM模型嘴部开合参数，实现低延迟、高自然度的口型联动。

### 4.5 写实数字人表达通道 — WebRTC视频流输出

#### 4.5.1 架构定位

WebRTC写实数字人可视化输出通道，作为大语言模型应答的**多模态写实表达层**，将纯文本/语音应答升维为「照片级真实人脸视频流 + 流式语音 + 实时口型与微表情同步」的联合输出范式。适用于正式心理咨询、高代入感倾诉等偏好真人写实风格的场景。

#### 4.5.2 渲染架构

采用 **云端GPU渲染视频帧 + WebRTC低延迟推流** 架构，依托真人写实人脸驱动算法（Wav2Lip/Musetalk），根据TTS音频时序特征实时生成匹配口型、瞬目、面部微动的连续视频帧，经GPU编码后通过WebRTC推流至端侧。端侧仅执行视频流播放，无渲染算力要求，全终端兼容。

#### 4.5.3 核心能力

| 能力域 | 实现描述 |
|-------|---------|
| 全真人脸实时驱动 | 基于音频面部驱动算法，根据TTS音频特征实时生成真人口型、眉眼微动、头部轻柔摆动 |
| WebRTC低延迟推流 | 基于UDP传输，帧级纠错、弱网自适应降码率，全链路延迟稳定控制在600-900ms |
| 帧级音画同步 | 云端帧级时间戳绑定，TTS音频、人脸帧、视频编码时序对齐，同步误差≤20ms |
| 双工实时打断 | 端侧VAD人声检测，用户插话即时中断云端渲染与推流，重置会话上下文 |

## 5. 全链路交互时序规范

全链路交互时序严格标准化，消除输入感知、语义推理、多模态表达之间的时序失步：

| 时序阶段 | 触发条件 | 数据流向 | 端侧行为 |
|---------|---------|---------|---------|
| 多模态输入采集 | 用户提交文本/语音/摄像头授权 | 端侧→云端 | 文本上行、ASR流式识别、MediaPipe端侧推理 |
| 输出模态路由 | 云端解析`outputMode`字段 | 云端内部 | 激活输出模态注册表中对应处理器组合 |
| 思考态切入 | 输入提交瞬间 | 云端→端侧 | 下行思考态指令，激活输出通道切换思考表情 |
| 情绪动作执行 | 大模型产出首行指令 | 云端→端侧 | 下行正式表情+动作指令，各输出通道执行动画 |
| 正文流式输出 | 首行解析完成 | 云端→端侧 | 持续流式推送对话文本，端侧渲染打字机效果 |
| 语音同步播报 | 正文推送同步 | 云端→端侧 | TTS音频流下行，端侧播放+驱动口型同步 |
| 形象同步表达 | 语音播报同步 | 云端→端侧 | 2D/3D形象表情动作驱动 / 数字人视频帧推流 |
| 状态复位 | 对话结束且音频播完 | 端侧自治 | 所有输出通道复位至待机状态 |

## 7. 性能优化策略

| 优化维度 | 实施策略 | 预期效果 |
|---------|---------|---------|
| 面部推理加速 | WASM计算委托GPU delegate执行 | 单帧推理延迟稳定在20-50ms |
| 帧间节流 | 300ms推理间隔控制 | 降低设备功耗与CPU占用率 |
| 三级流水线 | LLM流式输出→TTS流式合成→音频流式推送 | 端到端语音响应延迟压缩至首包到达时间 |
| ASR长连接复用 | WebSocket全双工连接按用户维度复用 | 消除反复建连开销，降低首字识别延迟 |
| 资源懒加载 | 模型CDN预取+推理引擎懒初始化 | 首屏加载性能无劣化 |
| WebGPU加速 | VRM三维渲染委托WebGPU并行计算 | 端侧渲染帧率稳定在30fps+ |
| 优雅降级 | 摄像头/麦克风/渲染不可用时自动降级为可用模态组合 | 核心对话功能可用性无损失 |

## 8. 方案优势总结

| 优势维度 | 价值描述 |
|---------|---------|
| 多模态感知完整性 | 文本+语音语调+面部微表情三维度联合感知，构建用户真实情绪状态的完整信号空间，显著增强模型对隐性情绪的捕捉能力 |
| 多模态表达丰满度 | 文本+语音+2D形象+3D形象+数字人五通道协同输出，按场景需求灵活组合，实现应答的情感丰满度与拟人化表达 |
| 模态架构可扩展性 | 输入/输出双模态注册表驱动，新增模态只需实现标准接口并注册，无需修改核心调度逻辑，从根本上保障项目的模态扩展性与场景适配能力 |
| 场景自适应适配 | 五种输出模态组合覆盖日常陪伴、沉浸式陪伴、正式咨询、纯文本、低配终端等全场景需求，自动降级保障体验连续性 |
| 语义零失步 | 单模型同源推理，文本、情绪、动作统一决策，从根本上消除多模型并行推理的语义错位风险 |
| 流式体验完整 | 头部指令+尾部正文混合输出格式，规避JSON全量结构化输出对流式交互的阻塞，保留原生逐Token实时体验 |
| 隐私合规架构级保障 | 原始生物特征数据零出域传输，仅上行结构化数值特征，满足心理咨询场景个人信息保护合规要求 |
| 端云弹性伸缩 | 感知算力下沉端侧（面部推理、虚拟人渲染），决策算力汇聚云端（LLM推理），算力随用户规模水平扩散 |

## 9. 落地约束规范

- 所有虚拟人表情与动作仅由大模型语义决策产出，禁止端侧自主触发核心交互动作，保证交互逻辑全局一致性
- 头部控制指令仅在单轮对话首次输出中出现，正文全程禁止出现任何标记字符，保障文本纯净性与TTS合成质量
- 面部情绪感知模块定位为辅助输入模态，非独立情绪诊断系统，不输出临床级情绪评估结论
- 心理对话场景严格采用克制化动作库，禁止高频、夸张、娱乐化动画，贴合陪伴类产品调性
- 全链路动画时序须严格遵循「多模态输入采集 → 输出模态路由 → 思考态切入 → 情绪动作执行 → 正文流式输出 → 语音同步播报 → 形象同步表达 → 待机复位」的固定状态流转逻辑，禁止时序错乱
- 端侧所有模型参数与动画资源统一版本固化管理，禁止运行时动态加载未校验资源
- 面部感知与虚拟形象功能均须支持独立启停，任一模态不可用时自动降级为可用模态组合，核心对话交互功能完全可用
- 输出模态组合须由`outputMode`字段显式声明，禁止端侧自行决定输出模态，保障端云输出一致性
- 新增输入/输出模态须实现标准模态接口并注册至对应模态注册表，禁止绕过注册表直接接入调度逻辑

> 注：本方案构建心聆AI对话系统的可扩展多模态交互全链路，输入侧涵盖文本、语音、面部视频表情三维度联合感知，输出侧涵盖文本、语音、二维虚拟形象（Live2D）、三维虚拟形象（VRM）、写实数字人（WebRTC）五通道协同表达。输入/输出双模态注册表驱动架构从根本上保障模态扩展性，后续可根据场景需求灵活扩展输入模态（如生理信号、环境感知等）与输出模态（如AR/VR沉浸式表达、全息投影等），实现从用户多模态感知输入到系统多模态协同表达输出的端到端闭环，非多个独立系统的简单拼接。
